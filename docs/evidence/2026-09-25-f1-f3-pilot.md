### Implementation (`d2bc220`, `20fe3b8`, `1ef8aae`, and the scope-key refactor `968fb1e`)

- **Sweeps** (`acquisition/sources/ebay.py`, `CATEGORY_SWEEPS`, pilot defaults the owner can tune):
  GPU `ebay:gpu:rtx-3090` (27386, "RTX 3090"); RAM `ebay:ram:ddr4-ecc-rdimm-32gb` (11210, "32GB
  DDR4 ECC RDIMM"); CPU `ebay:cpu:epyc-7302` (56088, "EPYC 7302"). All use
  `filter=buyingOptions:{FIXED_PRICE}`, because an auction's current bid is not an acquirable price.
  Each listing carries `category_hint` and the MS2-D-12 `collection_scope`. The legacy drive keyword
  sweep is unchanged (one GET, scope and hint `None`).
- **Pagination:** `limit=200`, offset paging, 5 pages per sweep, at most 15 pages per run (checked at
  import). `total` never drives paging.
- **Completeness:** a category sweep is complete only if it is a **single page** with no `next`, a
  stable integer `total` no larger than the items seen, and no parse drop. Every multi-page sweep is
  incomplete (`multi_page_unprovable`): the verifier showed that offset paging over a live, re-ranked
  set can skip an item while `total` and the distinct-id count still agree, which would have delisted
  a live listing. Other reasons: `page_cap`, `silent_window_end`, `total_unstable`, `parse_drop`,
  `time_budget`, `page_failed:<cause>`.
- **Per-scope absence:** the pipeline applies gating, continuity, and absence per swept scope, in
  deterministic order, each in its own transaction. Every scope's delist excludes every key seen
  anywhere in the run. A complete GPU sweep cannot delist drive, RAM, CPU, or another query's
  listings. Remote providers never take the multi-scope path.
- **Failure isolation:** the drive GET runs first. Category sweeps share a 60 s deadline inside the
  120 s run timeout. Any exception on a category page, or a malformed summary, fails only that sweep.
- **Quota:** `probe()` (the 120 s heartbeat) is one GET, and a heartbeat-fired FULL run skips the
  category sweeps. Budget: 720 probes + 144 × (1 + ≤15) ≈ 3,024 calls/day, under 5,000. A 401
  re-mint adds one GET.
- **Per-run record:** `ScraperRun.detail_json["scopes"]` (`contracts.SCOPE_OUTCOMES_KEY`) holds
  `scope_key`, `pages`, `complete`, `reason`, `continuity`, and `delisted` for each scope.
- **Verification:** 31 category-sweep tests; the 18 frozen eBay tests are unchanged. Two independent
  verifier passes: the first refuted multi-page completeness and found three lower-severity defects,
  all fixed with mutation-checked tests; the second found no refutation, and its one residual finding
  (a malformed category summary failing the run) is fixed in `1ef8aae`.

## F3: `pilot_report`

`manage.py pilot_report [--since ISO | --days N] [--source KEY …] [--json]` (`0b2246b`, module
`acquisition/pilot_report.py`, JSON schema `hw-radar/pilot-report/v1`) groups evidence by source,
provider, collection scope, and category. For each group it reports: run count; the
complete/truncated/partial/failed distribution and completeness rate; identifier (MPN/model)
coverage and resolution grain; condition coverage; shipping coverage (free, paid, unknown);
freshness (newest observation age, gap between successful runs); parser and matcher unknowns;
failure classes and recovery; and cost. Apify cost comes from ledger debits. Local and API sources
print "no direct provider cost (not metered)" and never invent a dollar figure. Missing evidence is
printed as "not recorded", and `unknown` never counts as success. It is read-only (a test asserts
no writes).

### Pilot findings

1. **GPU, RAM, and CPU listings resolve to nothing.** No GPU, RAM, or CPU reference rows existed:
   the pilot database was migrated but not seeded, and production has 0 `gpu_spec`, `ram_spec`, and
   `cpu_spec` rows too. The first-party seeds (CPU 9, GPU 8, RAM 2) load through `import_refdata`,
   which has not been run in production. Category auto-accept also stays off until a category corpus
   is ratified (risk R4). A category F6 proof therefore needs the watched product seeded first.
2. **Condition coverage is 0% on every source.** The eBay connector does not map Browse's
   `condition`/`conditionId`, and the merchant connectors do not capture it. A watch with a condition
   requirement would evaluate `unknown`. This is not changed here: condition feeds the drive
   matcher's variant grain, so it waits for the MS-1e ratification to avoid moving the oracle
   mid-audit.
3. **Live churn is real.** The RTX 3090 sweep saw `total` move within one five-page sweep, which
   confirms the single-page completeness rule.
4. **Two connector defects found and fixed during the pilot:** goHardDrive's category URL had
   drifted to External Enclosures and its title selector returned empty text (`2c8bce6`). Every
   Scrapy network crawl started from an asyncio loop timed out because Twisted's thread pool never
   started, so hostname lookups never ran (`b9e01a1`, with a DNS-path regression test).
5. **WD titles carry no part number.** The part number is only in the SKU key, so WD listings cannot
   resolve by title (MS-1e packet finding F2).
