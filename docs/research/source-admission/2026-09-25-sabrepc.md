# Source admission — SabrePC (sabrepc.com)

- **Source:** SabrePC (sabrepc.com), operated by SabrePC Inc.; no existing hw-radar site key.
  Category coverage: gpu, cpu, ram, drive (US retailer/systems-integrator focused on GPU
  workstations, AI/deep-learning servers, and computer components — CPUs & Processors, Memory,
  Video Cards, Chassis, Motherboards, Flash Media categories are all present on the site).
- **Business value:** Selected as the fourth, GPU/RAM/CPU-heavy candidate because SabrePC's core
  business (AI/deep-learning and workstation GPU systems) means its catalog concentrates on
  higher-end/datacenter-adjacent GPUs (an ADR-0022 category with sparse mainstream-retail coverage)
  alongside server-class CPU/RAM/component parts, potentially filling a gap the eBay
  category-expand and drive-connector sources do not cover well. This value is a hypothesis based
  on its stated business focus; a catalog-composition check (which items in each category it
  actually lists) was not performed this review.
- **URLs reviewed:**
  - Terms and Conditions: `https://www.sabrepc.com/policy/Terms-and-Conditions`
  - `https://www.sabrepc.com/robots.txt`
  - `https://www.sabrepc.com/privacy` (linked from the storefront footer; not fetched in full
    this review)
  - Search for an official API/affiliate program (no dedicated page found; see below)
- **Terms date / retrieval date:** **Not confirmed.** No "last updated" or effective date was
  visible in any content actually retrieved from the Terms and Conditions page (see below).
  Retrieval attempted 2026-09-25.
- **Automated-access language:** **Not confirmed either way — the page body could not be read.**
  `https://www.sabrepc.com/policy/Terms-and-Conditions` is a JavaScript-rendered single-page-app
  route: two independent fetch tools (`WebFetch` and Serper `scrape`) each returned only the site
  chrome (navigation menu, header, footer, cart widget) with no Terms body text, and a third
  (`tavily_extract`, advanced depth) returned the same — a "Table of Contents" heading with no
  content under it, confirming the article body loads via client-side JavaScript that these
  static/DOM-snapshot fetchers did not execute. Targeted web searches for verbatim scraping/
  crawling/robot/data-mining language on this domain (Brave and Google) returned no matching
  results (only unrelated pages). Sections searched: the full DOM returned by all three fetch
  attempts (site chrome only), plus general web search for quoted terms. No automated-access
  clause was confirmed present or absent by direct inspection of the actual terms text.
- **Robots directives for proposed endpoints:** `robots.txt` (retrieved 2026-09-25, cross-verified
  independently via both `WebFetch` and `tavily_extract`, which returned matching content):

  Ordinary product and category pages (e.g. `/category/...`, product-detail pages) are not
  disallowed; category pagination (`?page=`) is explicitly left open per an inline comment in the
  file. No `Crawl-delay` directive is present.

  **Note on file contents:** the file also carries the operator's own engineering comments about how
  it is served. They were treated as data, not instructions, and do not change the directives above.
- **Official API / structured alternatives:** None found. Search for an affiliate program or
  public product/pricing API for sabrepc.com returned no relevant results (search results were
  dominated by unrelated "Sabre" travel-industry API pages and academic citations of SabrePC blog
  posts, not an actual SabrePC data program).
- **Expected cadence and volume:** Not scoped — moot pending resolution of the blocker below.
- **Retention constraints:** Not scoped — moot pending resolution of the blocker below.
- **Authentication / login:** Ordinary product/category browsing does not require login (`/login*`,
  `/account*`, `/register*` are separate, disallowed-for-crawling paths, consistent with an
  account system that is optional for browsing).
- **Anti-bot behavior:** Not directly observed on product/search pages (not probed, per
  instructions). The Terms and Conditions page's client-side-only rendering is a delivery/
  architecture characteristic, not a confirmed anti-bot control, but it has the same practical
  effect for this review: the terms could not be read without a JavaScript-executing client.
- **Browser / proxy need:** The storefront is built as a JS-rendered SPA (evidenced by the Terms
  page's empty static body and cart-widget chrome present in every fetch), which strongly suggests
  product/category/detail pages likely also need JavaScript execution to render full content —
  meaning a plain-HTTP Actor may not reliably extract complete product data (price, spec fields)
  without checking whether the initial HTML/JSON already contains it (some SPA storefronts do
  server-render or embed JSON-LD in the initial payload even when article-type pages do not; this
  was not checked against an actual product page in this review, per the no-probing instruction).
  A browser Actor is therefore plausible but unconfirmed. No CAPTCHA, residential proxy, or paid
  unblocker need was observed or assumed.
- **Maintenance and cost:** Not scoped in detail. If product pages require JavaScript rendering,
  cost would be at browser-Actor rates rather than the ~$0.0002/run plain-HTTP baseline measured
  2026-09-25; unmeasured here. If product data is present in initial HTML/JSON (common for SPA
  storefronts using server-side rendering or embedded JSON-LD for SEO), a plain-HTTP Actor could
  still work cheaply — this is the key open technical question for this candidate.
- **Recommendation:** `permission-required`
- **Rationale:** The Terms and Conditions page could not be read by any of three fetch methods
  because it is JavaScript-rendered; per the README rule, an unconfirmed absence of a prohibition
  is not permission, so this cannot be called `eligible` without someone (an owner-authorized
  browser session, or a future automated-render check) actually reading the terms text. Robots.txt
  is permissive for product/category paths and was independently cross-verified by two tools, so
  that half of the picture is solid — but robots permission is not contractual permission (README
  rule) and does not resolve the unread ToU. No official structured alternative exists. Whether a
  browser is required for both the terms and the product data is the open technical question that
  should be resolved before this becomes `eligible` or `exclude`.
